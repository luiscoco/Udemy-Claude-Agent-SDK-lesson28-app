01

Use allow entries as pre-approval

allowedTools adds allow rules; it is not a complete inventory or a universal whitelist. The default experiment leaves Write available and sends that unlisted call to a denying callback. Reads inside the working directory can also be safe built-in approvals.

02

Distinguish removal from runtime denial

A bare Write deny removes that definition. A scoped Bash(rm *) deny keeps Bash available and rejects matching calls as written. The live shell experiment uses one disposable fixture and an independent exact-operation guard.

03

Match MCP globs correctly

An allow glob needs a literal server prefix, such as mcp__classroom__read_*. The live call on that server succeeds while the archive server call reaches the callback and is denied. The wildcard experiment verifies denied MCP execution while Read succeeds. In this pinned runtime MCP names remain in the reported snapshot, so inspect actual denial feedback.

04

Protect writes using Edit path rules

The live Edit(./protected/**) deny protects a directory even though the model requests Write. A separate Write to result.txt succeeds. Reference notes distinguish relative, single-slash source-anchored and double-slash absolute patterns; Write(path) is not an equivalent scoped write rule.

05

Load declarative project rules

The project experiment writes an actual .claude/settings.json in a fresh classroom directory and enables settingSources project. Its allow permits Read, deny protects a mock .env read and ask sends Write to the programmed callback.

06

Compare dontAsk with bypass

The reviewer pre-approves Read/Glob/Grep and uses dontAsk, so its attempted Write is denied without a callback. With bypass and only Read in allowedTools, an unlisted Write executes. Verify actual native results and host file checks.
