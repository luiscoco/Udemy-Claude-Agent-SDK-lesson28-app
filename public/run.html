Configure and run the app.

Install the SDK, configure your key and run the classroom comparisons.

01

Prerequisites

Install Node.js 24 or later, have API credit and model access, and install Git for Windows if the SDK needs Git Bash. Python is needed only to regenerate the student pages.

node --version
npm --version
02

Install and create your .env file

From presentations enter this app, install locked dependencies and preserve an existing .env. Enter your own model key privately. The mock .env used in one exercise is generated separately in a disposable directory.

cd .\agent-sdk\lesson28-allow-deny-rules
npm ci
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
03

Start the application

Keep the terminal open and use the startup URL. The app creates the local MCP servers and temporary fixtures. No GitHub token or Managed Agents resource IDs are needed.

npm start
# http://127.0.0.1:3128
04

Compare the four rule forms

Run allow fallback, bare deny, scoped deny and MCP wildcard deny. Check whether a tool is absent from the reported inventory or actually attempted and rejected.

npm run sample:env -- allow-fallback
npm run sample:env -- bare-deny
npm run sample:env -- scoped-deny
npm run sample:env -- wildcard-deny
05

Compare MCP globs, paths and project settings

Run the remaining rule experiments. Inspect the literal-server glob, protected Write denial and actual project allow/deny/ask behavior. The callback allows only the fixed classroom output in project mode.

npm run sample:env -- mcp-glob
npm run sample:env -- path-deny
npm run sample:env -- project-settings
06

Compare reviewer dontAsk with bypass

Both modes keep Write available. The reviewer denies it without a callback; bypass permits the unlisted write. Compare actual outputs instead of treating allowedTools as a universal restriction.

npm run sample:env -- reviewer-dontAsk
npm run sample:env -- bypass-unlisted
npm test

Your .env configuration

ANTHROPIC_API_KEY=your_api_key
CLAUDE_MODEL=claude-sonnet-4-6
PORT=3128
# Windows if needed: CLAUDE_CODE_GIT_BASH_PATH=C:/Program Files/Git/bin/bash.exe

Only your model key is required. Keep it local and restart after edits. Existing shell variables take precedence.

Troubleshooting

Use Node 24+, API credit and a supported model. Configure Git Bash on Windows if requested. If the port is occupied, use the printed existing-app URL or change PORT. Distinguish removed tools from denied attempts. For project rules, check settingSources includes project. Scoped write rules use Edit(path), not Write(path). Read native feedback and host file evidence before concluding that a rule matched.
